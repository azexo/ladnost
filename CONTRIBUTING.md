# Contributing Guidelines

Hello! 👋 Thank you for deciding to contribute to **Ladnost**. 
We welcome any kind of contribution: from fixing typos in the documentation to implementing complex architectural features.

This document will help you quickly understand how the development process works and how to ensure your Pull Request is reviewed and merged as smoothly as possible.

> 💡 **Pro Tip: Ask AI First!**  
> Before opening an issue or waiting for a maintainer's reply, try asking an AI assistant or reviewing the docs. Modern AI tools can often provide instant, accurate answers on how to set up the project, run tests, or understand the codebase architecture. Save time and get instant help!


## 🐛 Reporting a Bug

If you found a bug, please create an [Issue](https://github.com/azexo/ladnost/issues).  
To help us resolve it faster, please use the **Bug Report** template and include:
* The version of the project and your environment (OS, language/runtime version).
* Steps to reproduce the issue.
* Expected vs. actual behavior.
* Logs or screenshots (if applicable).

💡 **Important:** If you found a security vulnerability, **do not create a public Issue**. Please report it privately to [info@ladnost.ru].

## 💡 Suggesting a New Feature

Have an idea to improve the project? That's great!
1. First, check [existing Issues](https://github.com/azexo/ladnost/issues) to see if it's already being discussed.
2. If not, create a new issue using the **Feature Request** template.
3. We will discuss the idea, and only after the architecture is agreed upon should you start writing code.
